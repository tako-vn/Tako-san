## Audit Logs v1 contract

T21E retains `GET /accounts/{account_id}/audit_logs`, using sequential `page` and `per_page` pagination, with requested `per_page=1000` and a 50-page cap. The client's requested page sequence determines which page is being read. This is Audit Logs v1. The distinct v2 endpoint, `/accounts/{account_id}/logs/audit`, uses cursor pagination and a different event schema; it is outside this change and outside the runtime allowlist. A switch to v2 would need a separate review of D1 operation semantics.

Each successful page must contain an array result. The entire `result_info` object is optional consistency metadata: `page`, `per_page`, `count`, `total_count`, and `total_pages` may each be absent, including on every page. An empty `result_info` object is valid. The client does not need a response echo of `page` or `per_page` to continue its own page walk. If supplied, `page` must be a positive safe integer matching the requested page. `per_page` must be a positive safe integer no greater than the requested size and consistent whenever repeated across pages. `count` must be a non-negative safe integer equal to that page's result length and fit within the observed `per_page` when known. `total_count` and `total_pages` must be non-negative safe integers and consistent whenever repeated; accumulated events must not exceed `total_count`, and at the terminal empty page must equal it when known. Contradictory hints leave the audit incomplete; a hint's absence on any page does not. The receipt keeps requested page size distinct from any observed `per_page` hint and does not invent response metadata.

A successful terminal empty result page is the sole completeness signal, with no `result_info` required. Pagination advances by one requested page even after a short non-empty page, matching the official Cloudflare TypeScript SDK's v1 page walk more closely. The minimal response `{"success":true,"result":[]}` proves an empty audit set on page 1 and reports `pagesRead=1`. Pages of 1000, 143, then 0 events require all three responses and report `pagesRead=3`. The terminal empty page counts toward `pagesRead` but contributes no events. A `total_pages` hint never ends the walk by itself; the terminal probe can be one page beyond the last non-empty page. Reaching the 50-page cap with no empty page, an invalid response, or an HTTP failure leaves `complete=false` and operation counts unknown. An HTTP failure on page 1 means `available=false`; a later failure after a successful page means `available=true`, `complete=false`, with the failing HTTP status recorded.

The sanitized D1 event retains `actionInfo` (from `action.info`) and `actionType` (from `action.type`) as different fields. Exact `actionInfo` values `CreateDatabase`, `DeleteDatabase`, and `TimeTravel` identify the three counted operations; generic action types such as `create`, `delete`, or `update` do not. Numeric counts, including zero for a proven empty result, require `available=true`, `complete=true`, and `operationIdentityComplete=true`. Any relevant D1 event with missing or empty `action.info` makes operation identity incomplete and all three counts unknown. The artifact excludes actor email/IP, token identifiers, raw metadata, old/new values, and raw HTTP details.

## Two fixed refinement windows

Only these coarse T21D state-change intervals are candidates for adaptive refinement:

| Window | Start UTC | End UTC |
| --- | --- | --- |
| A | 2026-09-26T12:00:00Z | 2026-09-26T13:00:00Z |
| B | 2026-09-26T13:10:00Z | 2026-09-26T18:00:00Z |

The refinement target is an interval of at most 60 seconds where bookmark digests differ across its endpoints. The algorithm samples a midpoint only for an interval with different endpoint digests and a duration above 60 seconds. It retains both halves when the midpoint reveals a third state, and stops on equal endpoint digests. An equal-digest pair shows no net bookmark-state difference across the sampled endpoints; it does not exclude internal transitions. At most 96 additional bookmark GET requests are permitted across both windows; exhaustion preserves partial intervals with `refinement.complete=false` and `refinement.budgetExhausted=true`. A failed sample records its availability and HTTP status without inventing a digest or a negative conclusion. The receipt reports sampled timestamps, full SHA-256 bookmark digests, transition-containing intervals, completeness, resolution, and request use. Raw Time Travel bookmark handles exist only transiently in runner memory and never enter the receipt, artifact, logs, documentation, or PR description.

The frozen 13:00-13:10 equal-digest interval remains visible and is not resampled to seek a different conclusion. A refined interval only correlates a database-wide net state advance with a time range; it does not prove a recipe ingredient change, an external enrichment writer, a SQL import, or an actor. The writer, output, source artifact, execution, and ingestion pipeline remain unproven.
